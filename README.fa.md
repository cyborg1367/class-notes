# راه‌اندازی نسخهٔ جدید دفتر کلاس

> **اصلاح ۲.۷.۱:** ورود بخش‌ها واضح‌تر شده و مسیرهای جایگزین و تشخیص علت اجرا اضافه شده‌اند. فایل‌های عمومی را طبق `UPDATE-2.7.1.fa.md` جایگزین کن؛ SQL یا آپلود دوبارهٔ Storage لازم نیست.

> **نسخهٔ ۲.۷:** حرکت‌های کوتاه و یک‌باره هنگام اسکرول اضافه شده‌اند. برای ارتقا از نسخهٔ ۲.۶ فقط فایل‌های عمومی را مطابق `UPDATE-2.7.fa.md` جایگزین کن؛ SQL یا آپلود دوبارهٔ Storage لازم نیست.

> **نسخهٔ ۲.۶:** اجرای Python در جزوهٔ دوم و نوت‌بوک‌های آموزشی کاملاً انگلیسی برای هر دو جزوه اضافه شده‌اند. طبق `UPDATE-2.6.fa.md` فایل‌های عمومی را جایگزین و فقط دو نوت‌بوک را در Storage خصوصی آپلود کن؛ SQL جدیدی لازم نیست.

> **نسخهٔ ۲.۵:** محیط اجرای Python و NumPy به تمرین جزوهٔ اول اضافه شده است. برای نصب از نسخهٔ ۲.۴.۱، بستهٔ عمومی را مطابق `UPDATE-2.5.fa.md` جایگزین کن؛ SQL و آپلود دوبارهٔ Storage لازم نیست.

> **نسخهٔ ۲.۴.۱:** نمودار دوبعدی به کنار عنوان جزوهٔ دوم اضافه شده است. برای نصب فقط بستهٔ عمومی را مطابق `UPDATE-2.4.1.fa.md` جایگزین کن؛ اجرای SQL یا آپلود دوبارهٔ Storage لازم نیست.

> **نسخهٔ ۲.۴:** طراحی کاغذی تأییدشده روی سایت اعمال شده است. برای ارتقا از نسخهٔ ۲.۳ فقط بستهٔ public را مطابق `UPDATE-2.4.fa.md` جایگزین کن؛ تغییر Supabase و اجرای SQL لازم نیست.

> **نسخهٔ ۲.۳:** برای ارتقا از نسخهٔ ۲.۲ فقط فایل‌های عمومی را مطابق `UPDATE-2.3.fa.md` جایگزین کن؛ SQL جدیدی لازم نیست. بند نسخهٔ ۲.۲ زیر، برای نصب نخست یا ارتقا از نسخه‌های قدیمی‌تر است.

> **نسخهٔ ۲.۲:** اگر نسخهٔ ۲ یا ۲.۱ قبلاً نصب شده، فقط فایل `005_quiz_experience.sql` را در SQL Editor اجرا کن و فایل‌های public جدید را جایگزین کن. فایل‌های نصب اولیه را تکرار نکن. راهنمای ارتقا در `UPDATE-2.2.fa.md` است.

این نسخه برای همان GitHub Pages و همان پروژهٔ Supabase آماده شده است. ورود Google و نشانی Callback قبلی تغییر نمی‌کند. تنظیم عمومی فعلی پروژه در بسته حفظ شده است؛ به کلید Secret، رمز پایگاه داده یا Google Client Secret در فایل‌های سایت نیاز نیست.

## دو بسته را با هم اشتباه نگیر

| بسته | مقصد |
| --- | --- |
| `class-notes-v2-public.zip` | مخزن عمومی GitHub؛ برنامهٔ سایت و فایل‌های نمایشی |
| `class-notes-v2-INSTRUCTOR-ONLY.zip` | فقط نزد مدرس و داشبورد Supabase؛ شامل جزوه‌ها و پاسخ‌نامهٔ آزمون‌ها |

**بستهٔ INSTRUCTOR-ONLY و فایل‌های SQL محتوایی را در GitHub عمومی آپلود نکن.** فایل `003_content_and_quizzes.sql` متن کامل جزوه‌ها و پاسخ‌های درست را دارد. فقط پوشهٔ `storage-upload` از این بسته باید به فضای خصوصی فایل‌های Supabase منتقل شود.

## ۱. ابتدا سرویس کلاس را در Supabase آماده کن

بستهٔ INSTRUCTOR-ONLY را Extract کن. در SQL Editor همان پروژه‌ای که ورود Google را برایش تنظیم کرده‌ای، فایل `002_classroom.sql` را یک بار اجرا کن.

این فایل جدول‌های جدید، عضویت کلاس، آزمون‌ها، بررسی پاسخ‌ها، گزارش مدرس و باکت خصوصی `class-materials` را ایجاد می‌کند. جدول قدیمی `class_notes_answers` حذف نمی‌شود؛ پاسخ‌های قبلیِ دانشجوی عضو کلاس قابل دریافت‌اند.

اگر خطای «جدول یا Policy از قبل وجود دارد» گرفتی، فایل را دوباره اجرا نکن و جدول‌ها را پاک نکن؛ متن خطا و اینکه کدام فایل را اجرا کرده‌ای نگه دار. این فایل برای نصب نخست نسخهٔ ۲ است.

پس از موفقیت، فایل `003_content_and_quizzes.sql` را در یک Query دیگر اجرا کن. این فایل دو جزوه و دو آزمون را وارد می‌کند. تا وقتی متن سؤال‌ها تغییر نکرده می‌توان آن را دوباره اجرا کرد. برای تغییر آزمونی که دانشجوها پاسخ داده‌اند، نسخهٔ آزمون باید افزایش یابد؛ سیستم از بازنویسی بی‌صدای پاسخ‌نامهٔ نسخهٔ قبلی جلوگیری می‌کند.

برای نصب نخست نسخهٔ ۲.۲، پس از اجرای موفق فایل 003، فایل `005_quiz_experience.sql` را نیز در یک Query جدید اجرا کن. این مرحله فقط اطلاعات قالب ورودی و خلاصهٔ نتیجه‌ها را به API اضافه می‌کند.

## ۲. فایل‌های جزوه را در باکت خصوصی قرار بده

در Supabase به Storage برو و باکت `class-materials` را باز کن. **Public بودن آن باید خاموش باشد.** این باکت را فایل SQL ساخته است.

داخل باکت پوشهٔ `machine-learning` را بساز. ساختار `storage-upload` بسته را با همان نام‌ها حفظ کن:

| مسیر در باکت | چیزی که از کامپیوتر آپلود می‌کنی |
| --- | --- |
| `machine-learning/` | دو فایل JS و دو فایل PDF داخل همین پوشه |
| `machine-learning/diagrams/` | محتوای پوشهٔ diagrams |
| `machine-learning/prediction/` | محتوای پوشهٔ prediction |

می‌توانی پوشه‌ها را جدا بسازی و فایل‌های داخلشان را در سه نوبت آپلود کنی. نام پوشهٔ `storage-upload` نباید بخشی از مسیر داخل باکت شود. فایل‌های SQL را داخل باکت نریز. مجوز خواندن این فایل‌ها بر اساس عضویت فعالِ همان کلاس بررسی می‌شود.

## ۳. برنامهٔ عمومی را در GitHub جایگزین کن

از مخزن فعلی یک نسخهٔ پشتیبان محلی نگه دار. برای این انتقال استفاده از GitHub Desktop ساده‌تر از آپلود پراکندهٔ فایل‌هاست: مخزن `cyborg1367/class-notes` را Clone کن و بستهٔ public را Extract کن.

در نسخهٔ محلیِ مخزن، فایل‌های قدیمیِ مربوط به سایت را با ساختار بستهٔ public جایگزین کن. **`.git` و `.github` را نگه دار**؛ Workflow سالم قبلی لازم است. ساختار جدید در ریشهٔ مخزن باید شامل این‌ها باشد:

- `build.py`
- `check.py`
- `web/`
- `.github/` با همان Workflow قبلی

پوشه‌های قدیمی `assets`، `content`، `tools`، `supabase` و `tests` و فایل `site.json` برای ساخت عمومی جدید لازم نیستند؛ پس از تهیهٔ پشتیبان از مخزن عمومی حذفشان کن. به‌خصوص PDFها و متن جزوه‌ها نباید در ریشهٔ عمومی باقی بمانند. READMEهای قدیمیِ راه‌اندازی را نیز با راهنمای جدید جایگزین کن تا دو دستور متفاوت نداشته باشی.

پوشهٔ والدِ ZIP را وارد مخزن نکن؛ `web` باید مستقیم در ریشه باشد. در GitHub Desktop بخش Changes را بررسی کن، Commit بزن و Push origin را انجام بده. این کار باید همان GitHub Action قبلی را فعال کند. تنظیم Pages همچنان GitHub Actions می‌ماند؛ Workflow تازه یا Jekyll اضافه نکن.

اگر از مرورگر آپلود می‌کنی، کل پوشهٔ `web` و دو فایل Python را در ریشه آپلود کن و حذف فایل‌های قدیمی را هم انجام بده. تعداد فایل‌های بسته زیر سقف ۱۰۰ فایلِ هر بار آپلود نگه داشته شده است.

**محدودیت مهمِ انتقال:** جزوه‌هایی که قبلاً در مخزن عمومی منتشر شده‌اند، ممکن است در تاریخچهٔ Git یا کپی‌های قبلی باقی بمانند. این انتقال دسترسی به نسخهٔ جاری سایت و محتواهای خصوصی آینده را کنترل می‌کند؛ انتشار عمومیِ گذشته را پس نمی‌گیرد. برای محتوای تازه، فقط خروجی public را در GitHub بگذار و منبع خصوصی را نزد خودت نگه دار.

## ۴. حساب خودت را مدرس کن

بعد از موفقیت Action، به نشانی زیر برو و با Google خودت وارد شو:

`https://cyborg1367.github.io/class-notes/account/`

حساب باید در Authentication → Users پروژهٔ Supabase دیده شود. سپس فایل `004_owner.sql` را باز کن و فقط `OWNER_EMAIL` را با همان ایمیل ورود خودت جایگزین کن. این Query را در SQL Editor اجرا کن. ایمیل را در GitHub عمومی قرار نده.

اکنون در سایت به نشانی زیر برو:

`https://cyborg1367.github.io/class-notes/instructor/`

باید پنل مدرس، مدیریت عضویت‌ها و گزارش‌ها را ببینی. واردشدن با Google به‌تنهایی نقش مدرس نمی‌دهد؛ این مرحله فقط از داشبورد مالک پروژه انجام می‌شود.

## ۵. مسیر دانشجو را آزمایش کن

با یک حساب Google دیگر وارد سایت شو. در فضای کلاس، «درخواست دسترسی به کلاس» را بزن. تا پیش از تأیید، بازکردن مستقیم آدرس جزوه و آزمون هم نباید محتوا را نمایش دهد.

با حساب مدرس، درخواست را تأیید کن. با حساب دانشجو «بررسی دوباره» را بزن؛ حالا جزوه، دریافت PDF، تمرین و آزمون باید فعال شوند.

ابتدا حالت «تمرین با راهنما» را امتحان کن. بررسی و راهنما نمرهٔ نهایی نمی‌سازند. سپس حالت آزمون را انتخاب کن و یک بار ثبت نهایی انجام بده. نتیجه باید در داشبورد دانشجو و گزارش مدرس ظاهر شود. تعداد بررسی‌های تمرینی و راهنماهای استفاده‌شده همراه ثبت نهایی نگه داشته می‌شود.

با حساب دانشجوی سوم، نتیجه و پاسخ‌های حساب دوم نباید قابل دریافت باشند. حسابی که نقش مدرس ندارد نباید پنل و گزارش کلاس را ببیند. اگر برای آزمایش حساب Google هنوز برنامه در حالت Testing است، حساب‌های آزمایشی را در Test users گوگل وارد کن.

## رفتار آزمون‌ها

- هر یادداشت چهار سؤال چهارگزینه‌ای و دو سؤال تکمیل کد دارد؛ جمعاً ۱۰ امتیاز. هر جای خالی مستقل امتیاز می‌گیرد.
- بررسی و امتیازدهی در PostgreSQL انجام می‌شود؛ مرورگر نمرهٔ دلخواه ارسال نمی‌کند و پاسخ‌نامه در خروجی public نیست.
- در جای خالی، فقط قالب خواسته‌شده وارد می‌شود: عدد صحیح، شناسهٔ تابع یا آرایه، عملگر یا رشتهٔ داخل کوتیشن. پاسخ‌های معادلِ مجاز مانند `1` و `-1` برای محور آخرِ آرایهٔ دوبعدی پذیرفته می‌شوند. این بخش اجرای آزاد Python نیست.
- پیش‌نویس آزمون در مرورگر و سپس در حساب ذخیره می‌شود. موفقیت ذخیرهٔ حساب و خطای اتصال جدا نمایش داده می‌شوند.
- ثبت نهایی قابل ویرایش نیست؛ برای اصلاح، تلاش تازه‌ای انجام می‌شود. اولین نتیجه، بهترین نتیجه و تعداد تلاش‌ها جدا نگه داشته می‌شوند.
- در قطع ارتباط هنگام ثبت، همان درخواست دوباره بررسی می‌شود و تلاش تکراری ساخته نمی‌شود. تا روشن‌شدن نتیجه، پاسخ‌های آن ارسال قفل می‌مانند.
- نمرهٔ کامل در چند سؤال به معنی تسلط کامل یا تضمین تشخیص واقعیِ پزشکی نیست؛ گزارش‌ها با همین توضیح نمایش داده می‌شوند.
- دکمهٔ ذخیرهٔ جدول تمرین، پیش‌نویس شخصی است و با ثبت نهایی آزمون فرق دارد. تمرین آزاد برای استدلال و نوشتن کد مستقل باقی مانده است.

## عکس و ویرایش‌های آینده

فایل عکس قبلی در محیط در دسترس نبود؛ در این نسخه به‌جای تصویر شخص، حروف MA نمایش داده می‌شود. برای جایگزینی، عکس اصلی را دوباره بفرست. تصویر ساختگی از مدرس استفاده نشده است.

منبع ساخت در زیرپوشهٔ `author-source` بستهٔ خصوصی قرار دارد. این پوشه را در مخزن عمومی نگذار. برای افزودن یادداشت یا تغییر سؤال‌ها، از همین منبع خصوصی استفاده کن. خروجی public هیچ سؤال یا پاسخ‌نامه‌ای در خود ندارد و برای اضافه‌شدن متن تازه باید SQL محتوایی و فایل‌های باکت هم به‌روزرسانی شوند.

## بررسی‌های انجام‌شده و محدودیت آن‌ها

مسیرها و دارایی‌های ۹ صفحه، عدم وجود PDF و پاسخ‌نامه در خروجی عمومی، محاسبه‌های نمونه، رفتار رابط و مجوزهای پایگاه داده بررسی شده‌اند. آزمون SQL با PostgreSQL در محیط آزمایشی اجرا شده و کاربر ناشناس، عضویت در انتظار، دانشجوی فعال، مدرس و مدرسِ کلاس دیگر را پوشش می‌دهد. قالب جزوهٔ اول و پاسخ ندادن به تمرین دستگاه‌ها حفظ شده است.

چیدمان به‌صورت ایستا رندر و بازبینی شده است. ابزار مرورگرِ لازم برای QA سایت در این محیط در دسترس نبود؛ ورود واقعی Google، Storage پروژهٔ زنده و نمایش نهایی در مرورگر بعد از راه‌اندازی باید مطابق مرحلهٔ ۵ آزمایش شوند. اتصال Supabase زنده و انتشار GitHub از این محیط انجام نشده است.

برای تکرار آزمون‌های منبع خصوصی:

```bash
npm install --no-save linkedom@0.18.12 @electric-sql/pglite@0.3.14
python3 tools/create_quizzes.py
python3 build.py
python3 check.py
node --test tests/*.test.cjs
```
