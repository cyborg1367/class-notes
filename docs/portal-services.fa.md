# مرحلهٔ دوم: مرزبندی سرویس‌های فرانت‌اند

این تغییر روی مرحلهٔ تست مرورگر قرار می‌گیرد. رابط‌های React موجود، طرح کاغذی،
مسیر صفحات و قرارداد backend حفظ شده‌اند. این مرحله SQL یا Edge Function جدید ندارد.

## فایل اصلی را کجا تغییر بدهیم؟

`web/assets/portal.js` از این مرحله **خروجی build** است. منبع قابل ویرایش در
`frontend/portal/` قرار دارد. برای تولید مجدد از `npm run build` یا `npm run dev`
استفاده کن؛ ویرایش مستقیم فایل خروجی در build بعدی از بین می‌رود.

| فایل منبع | مسئولیت |
| --- | --- |
| `entry.ts` | ورودی bundle کلاسیک و سازگاری با تست‌های Node موجود |
| `services/config.ts` | اعتبارسنجی تنظیمات عمومی، آدرس بررسی پاسخ و مقصد بازگشت امن |
| `services/auth.ts` | اتصال به SDK فعلی، حل نشست با مهلت محدود و مالکیت listener ورود |
| `services/requests.ts` | اشتراک فقط درخواست‌های خواندن هم‌زمان و رد پاسخ حساب قبلی |
| `services/classroom.ts` | انتقال RPC، مهلت دریافت وضعیت و سازگاری دقیق با bootstrap قدیمی |
| `services/public-config.ts` | خواندن تنظیمات عمومی با timeout و امکان تلاش مجدد |
| `services/scripts.ts` | بارگذاری یک‌بارهٔ اسکریپت‌های عمومی با پاک‌سازی در خطا |
| `services/async.ts` | ابزارهای مشترک مهلت درخواست و لغو انتظار |
| `services/routes.ts` | ترتیب راه‌اندازی صفحه و پاک‌سازی منابع هنگام تغییر حساب |
| `quiz-format.ts` و `quiz-figure.mjs` | کمک‌تابع‌های موجود آزمون با قرارداد قبلی |
| `application.mjs` | اتصال موقت سرویس‌ها به آداپترهای صفحات موجود |

سرویس‌های TypeScript با `strict` بررسی می‌شوند. `application.mjs` هنوز JavaScript
و نقطهٔ اتصال موقت است؛ انتقال کل این فایل به معماری نهایی در این مرحله تمام نشده است.
React همچنان فقط دادهٔ نمایشی و action دریافت می‌کند؛ client و توکن نشست به کامپوننت‌ها
داده نمی‌شوند.

## قراردادهای حفظ‌شده

- SDK فعلی Supabase با PKCE و همان کلید `class-notes-auth:<base-path>` استفاده می‌شود.
- دادهٔ خصوصی، مجوز دسترسی، پاسخ بررسی کد، XP و draft در cache تنظیمات عمومی قرار نمی‌گیرند.
- فقط خواندن‌های هم‌زمانِ مشخص می‌توانند درخواست مشترک داشته باشند؛ نتیجهٔ کامل‌شده cache نمی‌شود.
- مسیر قدیمی `classroom_state` فقط برای خطای مشخص نبودن `classroom_bootstrap` فعال می‌شود؛
  خطای شبکه، خطای دسترسی یا پاسخ ناقص باعث این fallback نمی‌شود.
- تغییر حساب، انتظارهای قبلی را نامعتبر و منابع صفحه را پاک می‌کند. ادامهٔ دیررس نباید UI
  مربوط به حساب قبلی را وصل کند.
- صفحه‌ها همان script کلاسیک `portal.js` را می‌گیرند؛ bundle با Vite ساخته می‌شود و
  import پویای featureها و runtime مشترک React حفظ شده‌اند.
- امتیاز و دسترسی همچنان در سرور تعیین می‌شوند. اجرای آزمایشی کد یا وضعیت UI، XP نمی‌سازد.

## بررسی محلی در ویندوز

سرور توسعه را پیش از کپی فایل‌ها با `Ctrl+C` متوقف کن. محتویات `public-update`
را در ریشهٔ پروژهٔ موجود کپی کن و جایگزینی فایل‌های هم‌نام را بپذیر. این بسته تجمیعی است؛
لازم نیست بستهٔ مرحلهٔ قبل را دوباره اعمال کنی.

```powershell
cd E:\MyProjects\class-notes
npm.cmd ci
npm.cmd run check
npm.cmd run typecheck:browser
npm.cmd run test:browser
npm.cmd run dev
```

اگر مرورگرهای Playwright هنوز نصب نشده‌اند:

```powershell
npx.cmd playwright install chromium webkit
```

`npm run check` تست‌های Python، Node و TypeScript برنامه را اجرا می‌کند؛ تست‌های مرورگر
فرمان جدا دارند. جزئیات محدودهٔ آن‌ها در [browser-tests.fa.md](browser-tests.fa.md) آمده است.

## آنچه باقی مانده است

آداپتر داشبورد اکنون در `frontend/dashboard/route.ts` مستقل شده است؛ جزئیات در
[dashboard-route.fa.md](dashboard-route.fa.md) آمده است. آداپترهای سایر صفحه‌ها در
`application.mjs` هنوز باید feature به feature جدا شوند. همچنین
`coding-lab.js` همچنان هماهنگ‌کنندهٔ اجرایی لابراتور است؛ React بخش‌های نمایشی آن را
در اختیار دارد. تبدیل صرف فایل‌ها به TSX یا افزودن router برای سایت چندصفحه‌ای، هدف این مرحله نیست.
