# قرارداد صفحهٔ مطالعه، نسخهٔ ۱

مرجع طراحی، صفحهٔ یادداشت اول است: تصویر در چپ، متن در راست، مشخصات مدرس بالای شروع مطالعه، نوار سه نکته در پایین هدر، سپس ستون متن و سایدبار. در موبایل، متن و تصویر زیر هم و نکته‌ها در سه ردیف قرار می‌گیرند.

## مالکیت و ترتیب اجزا

`LessonTemplate.tsx` تنها محل ترکیب صفحه است. ترتیب آن ثابت است:

1. `LessonHero`: عنوان، مقدمه، تصویر، مشخصات مدرس و یک شروع مطالعه
2. `LessonHighlights`: دقیقاً سه نکتهٔ اصلی
3. `LessonLayout`: سایدبار و بدنهٔ مطالعه
4. `LessonContent`: بخش‌های آموزشی
5. `LessonPager`: قبلی/بعدی با ترتیب RTL
6. `LessonResources`: تمرین/آزمون، PDF و نوت‌بوک
7. `LessonFooter`: بازگشت به کلاس

تعداد و ترتیب موضوع‌های آموزشی با محتوای درس تعیین می‌شود؛ جای اجزای صفحه تغییر نمی‌کند. `ReaderDocument` فقط چرخهٔ دریافت منابع خصوصی، اتصال ابزارها و وضعیت مطالعه را مدیریت می‌کند. مشخصات مدرس و همهٔ اجزای صفحه نباید دوباره داخل متن درس نوشته شوند.

## محتوا و اجزای React

بدنهٔ خصوصی فعلی در Supabase حفظ شده است. `prepare.ts` مرز پاک‌سازی و سازگاری داده است. `content-model.ts` HTML پاک‌سازی‌شده را به مدل سند قابل استفاده توسط React تبدیل می‌کند. `LessonContent.tsx` پاراگراف، تیتر، فهرست، بخش، کد، جدول، شکل و نکته را با اجزای مشخص رندر می‌کند. رندر یکجای کل مقاله با dangerouslySetInnerHTML حذف شده است.

کدهای رنگ‌آمیزی‌شده و بخش‌های تألیفی هدر پس از پاک‌سازی، HTML محدود دارند. فرمول‌ها، SVG و ابزارهای قدیمی نیز به‌عنوان جزیرهٔ سازگاری، شناسه‌ها و قلاب‌های تعاملی‌شان را نگه می‌دارند؛ این بخش‌ها بازنویسی کامل به React نشده‌اند. تغییر پیشرفت مطالعه آن‌ها را بازسازی نمی‌کند. ظاهر عمومی متن در جزیرهٔ سازگاری تعریف نمی‌شود.

## استایل و اندازه‌ها

استایل اجزای جدید در CSS Modules کنار TSX آن‌هاست. استایل outline، پایان یادداشت و شکل آستانه نیز از paper.css به فایل کنار کامپوننت منتقل شده است. Vite همه را در `web/assets/reader-template.css` می‌سازد و build آن را فقط به مسیرهای lesson اضافه می‌کند. این فایل خروجی را دستی ویرایش نکنید.

قواعد پایه در `LessonTemplate.module.css` هستند:

| موضوع | دسکتاپ | موبایل |
|---|---|---|
| عرض متن | تمام عرض ستون موجود | تمام عرض ستون موجود |
| سایدبار | ۱۹۰؛ در عرض ۱۰۲۵ تا ۱۱۰۰، ۱۶۵ پیکسل | تا ۱۰۲۴ پیکسل، فهرست کشویی جای سایدبار را می‌گیرد |
| فاصلهٔ ستون‌ها | ۲۴؛ در دسکتاپ باریک، ۲۰ پیکسل | تک‌ستونی |
| متن | ۱۷ پیکسل، ارتفاع خط ۲ | تا ۷۶۰، ۱۶ پیکسل |
| کد | ۱۳ پیکسل | ۱۲ پیکسل |
| فاصلهٔ پاراگراف | ۱۴ پیکسل | ۱۴ پیکسل |
| نوار نکته‌ها | سه ستون RTL | سه ردیف |
| ارتفاع کد | کوچک‌تر از ۳۲rem و ۶۵٪ ارتفاع پنجره | همان قاعده |
| جدول | سربرگ زرد ملایم، فقط خطوط افقی | اسکرول داخل قاب، بدون اسکرول کل صفحه |

فونت و رنگ‌ها از توکن‌های موجود سایت می‌آیند. پاراگراف محدودیت جداگانهٔ ch ندارد. تیترهای بدنه با عرض واقعی می‌شکنند و nowrap ندارند. کد LTR و عبارت انگلیسی در متن جداشده از جهت RTL است. در چاپ محدودیت ارتفاع کد و سایدبار برداشته می‌شود.

## افزودن یادداشت بعدی

1. اطلاعات عمومی و مسیر منابع را مانند قبل به کاتالوگ اضافه کنید.
2. در `frontend/reader/lesson-presentation.ts` برای شناسهٔ درس دقیقاً سه نکتهٔ آموزشی روشن تعریف کنید. ساخت پروژه، نبودن این تعریف را خطا می‌داند. این فایل شامل متن خصوصی یا جواب آزمون نیست.
3. بدنهٔ خصوصی را طبق `docs/templates/lesson-body.html` آماده کنید. هر موضوع شناسهٔ پایدار داشته باشد؛ پیوند مرور سؤال‌ها به همین شناسه‌ها اشاره کند.
4. کد را با pre/code و language-python و خروجی را با language-text بنویسید. قاب، کپی و اسکرول خودکار ساخته می‌شوند.
5. جدول واقعی HTML و شکل با alt و figcaption بنویسید. از style درون‌خطی برای عرض، رنگ و فونت بلوک‌های استاندارد استفاده نکنید؛ مدل سند آن‌ها را حذف می‌کند.
6. PDF و نوت‌بوک و آزمون را با کد و متن تأییدشده هماهنگ کنید. مسیر فایل‌های فعلی تغییر نمی‌کند و ساخت پوشهٔ نسخه‌دار لازم نیست.
7. متن را با پاراگراف‌های معنایی بنویسید. قالب وظیفهٔ چسباندن خودکار جمله‌ها را ندارد.

برای یادداشت جدید، CSS عمومی هدر، متن، جدول، کد یا سایدبار ننویسید. اگر ابزار تعاملی متفاوتی لازم است، کامپوننت و استایل همان ابزار را اضافه کنید.

## صفحهٔ مرجع محلی

پس از `npm.cmd run dev` باز کنید:

`http://127.0.0.1:5173/__preview__/lesson/?reference=1&note=05`

این پیش‌نمایش از همان LessonTemplate و همان استایل نسخهٔ واقعی استفاده می‌کند؛ محتوای آن نمونه است و دانلود خصوصی غیرفعال است. کد طولانی، خروجی، جدول، شکل، فهرست و نکتهٔ آموزشی دارد. پارامتر note را از 01 تا 05 تغییر دهید تا نکته‌ها و ناوبری هر درس را ببینید.

## بررسی تغییر

- `npm.cmd run check`: ساخت، TypeScript و تست‌های پایتون و جاوااسکریپت
- `npm.cmd run typecheck:browser`: بررسی نوع تست‌های مرورگر
- `npm.cmd run test:browser:chromium`: کنترل چیدمان واقعی در مرورگر نصب‌شدهٔ محلی

تست‌های DOM پنج درس و اجزای مرجع را بررسی می‌کنند: یک عنوان و شروع مطالعه، یک مشخصات مدرس، سه نکته، کپی کامل، جدول، حفظ نمودارها و منابع. تست‌های مرورگر عرض پاراگراف، ترتیب RTL، رنگ‌بندی ساختاری جدول، اندازهٔ کد و چینش نوار را بررسی می‌کنند. تست‌های مرورگر باید در محیط دارای مرورگر اجرا شوند؛ پاس‌شدن تست‌های DOM به معنی بازبینی تصویری نیست.

متن خصوصی کامل یادداشت‌های اول تا چهارم در ZIP پروژهٔ عمومی موجود نبود؛ سازگاری آن‌ها با نمونه‌های نماینده و قلاب‌های موجود بررسی می‌شود و بازبینی با متن واقعی نیز در لوکال لازم است.
