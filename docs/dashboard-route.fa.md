# مرحلهٔ سوم: مالکیت مستقل صفحهٔ داشبورد

این مرحله روی نسخهٔ دارای تست مرورگر و سرویس‌های portal قرار می‌گیرد؛ فایل‌های هر دو
مرحلهٔ قبل در مخزن اصلی ثبت شده‌اند. طراحی و CSS داشبورد تغییر نمی‌کند.

## مرز مسئولیت‌ها

| بخش | مسئولیت |
| --- | --- |
| `frontend/dashboard/route.ts` | بارگذاری تنبل feature، مالکیت root و کنترلر، اشتراک راه‌اندازی هم‌زمان و reset هنگام تغییر حساب |
| `frontend/dashboard/controller-contracts.ts` | قراردادهای تایپ‌شدهٔ context، renderer، کنترلر و سرویس‌های مورد نیاز |
| `frontend/dashboard/dashboard-controller.mjs` | دریافت و تبدیل داده‌ها، snapshotهای bootstrap یا fallback، نتایج آزمون، نشان‌ها و خلاصهٔ مرور |
| `frontend/dashboard-page.tsx` و کامپوننت‌های داشبورد | رندر React و تعامل‌های نمایشی |
| `frontend/portal/application.mjs` | اتصال وابستگی‌ها و ثبت adapter در چرخهٔ مشترک صفحات |

adapter به SDK، توکن، کلید خصوصی و schema دیتابیس وابسته نیست. اطلاعات ورود و دریافت
وضعیت مشترک کلاس همچنان از سرویس‌های موجود می‌آید. کنترلر موجود JavaScript باقی مانده
و قرارداد ورودی/خروجی آن مستند شده است؛ adapter و قراردادهای جدید TypeScript strict هستند.

## رفتارهای حفظ‌شده

- snapshot موجود در bootstrap دوباره با RPC جدا درخواست نمی‌شود.
- اگر دریافت بخشی از پیشرفت شکست بخورد، امتیاز نامشخص به صفر تبدیل نمی‌شود.
- نتایج آزمون، لینک رسید، مسیر ادامهٔ یادگیری و `#results` حفظ می‌شوند.
- نشان‌های مرور با همان کلید حساب در مرورگر ذخیره می‌شوند و XP یا دسترسی ایجاد نمی‌کنند.
- خلاصهٔ دیررس مرور، فیلتر و نشان‌های انتخاب‌شده را از نو نمی‌سازد.
- درخواست عضویت و به‌روزرسانی وضعیت از همان RPCهای قبلی استفاده می‌کنند.

## مالکیت و خطا

تا پیش از ایجاد کنترلر، درخواست‌های هم‌زمان صفحه یک بارگذاری feature مشترک دارند.
کنترلر موجود برای بارگذاری بعدی reuse می‌شود. تغییر نسل نشست، شناسهٔ حساب یا host،
کار قدیمی را نامعتبر می‌کند. `reset()` ابتدا مالکیت قبلی را باطل و سپس کنترلر و fallback
را پاک می‌کند؛ adapter برای حساب بعدی قابل استفاده می‌ماند.

در مسیر خطای قدیمیِ بارگذاری bundle داشبورد، تابع `loadingError` بیرون از محدودهٔ
تعریفش فراخوانی می‌شد. حالا کارت خطای مشترک React با دکمهٔ «بازخوانی داشبورد» نمایش داده
می‌شود. دکمهٔ بازخوانی، کل سند را حتی در آدرس `#results` با حفظ همان anchor دوباره
بارگذاری می‌کند؛ وضعیت ناموفق بارگذاری ماژول نیز از نو شروع می‌شود. خطای
startup داشبورد به معنی خارج‌شدن حساب از ورود نیست. fallback دیررس نیز پیش از اتصال،
مالکیت فعلی را بررسی می‌کند.

## بررسی محلی

پس از کپی محتویات `public-update` در ریشهٔ پروژه، اجرا کن:

```powershell
npm.cmd run check
npm.cmd run typecheck:browser
npm.cmd run test:browser
npm.cmd run dev
```

dependency جدیدی اضافه نشده است. اگر در این checkout هنوز dependencyها نصب نیستند،
ابتدا `npm.cmd ci` را اجرا کن. مرورگرهای Playwright همان نسخهٔ مرحلهٔ قبل هستند.

با حساب خودت، داشبورد، نتایج آزمون، نشان‌کردن یک یادداشت، reload و ورود/خروج را بررسی کن.
در مرورگر خودکار، backend، حساب و محتوای خصوصی ساختگی هستند؛ این تست‌ها تأیید اتصال
زندهٔ Google، Supabase یا سرویس بررسی پاسخ نیستند. فایل‌های backend و Secretها در این
مرحله تغییری ندارند.
