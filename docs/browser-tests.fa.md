# تست مرورگر خروجی واقعی سایت

این مجموعه خروجی `dist` را پس از build روی `127.0.0.1:4174` سرو می‌کند.
HTML، CSS، bundleهای React، script کلاسیک portal و SDK موجود Supabase همان فایل‌های
ساخت‌شده هستند؛ سرور تست آن‌ها را دوباره با Vite تبدیل نمی‌کند و SPA fallback ندارد.

## اجرای محلی

Node.js 24 و Python مطابق نسخه‌های پروژه لازم است. در PowerShell:

```powershell
npm.cmd ci
npx.cmd playwright install chromium webkit
npm.cmd run typecheck:browser
npm.cmd run check
npm.cmd run test:browser
```

برای اجرای فقط سه اندازهٔ Chromium یا دیدن گزارش:

```powershell
npm.cmd run test:browser:chromium
npm.cmd run test:browser:report
```

پورت 4174 باید آزاد باشد؛ سرور از قبل اجراشده reuse نمی‌شود. در صورت نیاز پورت دیگری بده:

```powershell
$env:E2E_PORT = '4175'
npm.cmd run test:browser
Remove-Item Env:E2E_PORT
```

## پوشش

۲۵ سناریو در چهار پروژه اجرا می‌شوند: دسکتاپ Chromium با عرض ۱۴۴۰، موبایل Chromium
با عرض ۳۹۰ و ۳۶۰، و WebKit موبایل با عرض ۳۹۰ پیکسل؛ مجموعاً ۱۰۰ اجرا.

- hydration صفحهٔ اصلی، جست‌وجو و موضوعات دوره، لینک لابراتورها و منوی موبایل با Escape و فوکوس.
- جلوگیری از نمایش محتوای محافظت‌شده برای مهمان و عضو در انتظار تأیید.
- ساخت درخواست ورود Google با callback محلی و PKCE؛ این تست وارد حساب واقعی Google نمی‌شود.
- هر چهار قالب یادداشت، تصویر خصوصی آزمایشی، دانلود PDF آزمایشی، پیشرفت مطالعه و ترتیب RTL قبلی/بعدی.
- هر چهار لابراتور، نام فایل، ابزارهای اجرا و بررسی، draft پس از reload و پس از شکست ذخیرهٔ ابری.
- خطای پاسخ بررسی، حفظ کد و استفادهٔ مجدد از شناسهٔ ارسال هنگام تلاش دوباره.
- داشبورد، خطای backend و تلاش مجدد، خروج از حساب، اعلان خوانده‌نشده، دفتر مرور و محدودیت رابط مدرس.
- پیش‌نویس آزمون، عدد فارسی، تأیید ارسال، رسید نتیجه و جلوگیری از بیرون‌زدگی افقی صفحه.
- گزارش مدرس، جزئیات دانشجو و پاسخ ذخیره‌شده با دادهٔ آزمایشی.

در رسید آزمون، جدول و کد باید داخل بخش خودشان اسکرول افقی داشته باشند؛ document نباید
از viewport عریض‌تر شود. اصلاح CSS همراه این مجموعه برای همین رگرسیون است.

## دادهٔ آزمایشی و محدودیت‌ها

fixtureهای صریح تست، نشست ساختگی، RPC، Storage، realtime و پاسخ بررسی را برای
`https://classroom-e2e.supabase.co` آماده می‌کنند. درخواست شبکهٔ غیرمنتظره رد و به‌عنوان
خطا گزارش می‌شود. مسیر اجرای worker نیز پیام‌های ساختگی دارد. این تست‌ها به production
وصل نمی‌شوند و SQL، RLS، Edge Function، E2B، اجرای واقعی Python یا صحت آموزشی نمره‌دهی
را تأیید نمی‌کنند. secret یا حساب واقعی برای اجرای آن‌ها لازم نیست.

شبیه‌سازی موبایل جای تست روی iPhone واقعی، صفحه‌کلید مجازی، screen reader یا بررسی کامل
دسترس‌پذیری را نمی‌گیرد. جهت RTL، خروج از عرض صفحه و برخی جایگیری‌های مشخص بررسی می‌شوند؛
تأیید تمام جزئیات بصری به بازبینی انسانی نیاز دارد.

خطاهای JavaScript و hydration تست را fail می‌کنند. تنها استثنای ثبت‌شده، رفتار شناخته‌شدهٔ
WebKit هنگام لغو درخواست presence ساختگی در تعویض سند است
([Playwright #43120](https://github.com/microsoft/playwright/issues/43120)).
این استثنا فقط همان endpoint، متن خطای مشخص و زمان navigation را می‌پذیرد و در گزارش
تست پیوست می‌شود؛ بقیهٔ خطاهای شبکه یا صفحه نادیده گرفته نمی‌شوند.

## CI

workflow مستقل `Browser regression tests` روی pull request به main، push روی main و اجرای
دستی فعال است. گزارش HTML و trace خطا با دادهٔ آزمایشی ۷ روز نگه داشته می‌شود.
این workflow تنظیمات deploy کلادفلر یا branch protection را تغییر نمی‌دهد؛ پس وجود آن به‌تنهایی
تضمین نمی‌کند deploy تا پایان تست مرورگر منتظر بماند.

`E2E_CHROMIUM_EXECUTABLE` فقط برای محیط‌هایی است که Chromium از قبل فراهم شده؛ در نصب
عادی نیازی به آن نیست. در Linux/CI می‌توان وابستگی‌ها را با
`npx playwright install --with-deps chromium webkit` نصب کرد.
